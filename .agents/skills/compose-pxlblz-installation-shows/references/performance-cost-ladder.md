# Applying the Visual Performance Plan to an Installation Show

The `co-design-pxlblz-visual-performance` skill owns the general cost model and Visual Performance Plan. This reference applies that plan to Installation Show structure.

## Composition ladder

Climb only when the cheaper rung cannot produce the required physical picture.

| Rung | Typical Show material | Use |
| --- | --- | --- |
| 1. Placement variation | timing, properties, palette, phase, masks | make one visual voice perform several roles |
| 2. Shared identity | one Pattern instance across Zones or Scenes | preserve family behavior with one state and clock |
| 3. Affine and address Effects | translate, scale, rotate, mirror, wrap | adapt shared material to physical instruments |
| 4. Hard routing and Cuts | selectors, complete ranges, hard boundaries | change ownership or visual law cheaply |
| 5. Sparse parameter data | small per-member or per-boundary records | vary repeated structure without copied programs |
| 6. Selective transition work | one justified motion, blend, or snapshot policy | make an important boundary into an event |
| 7. Independent identities | unique Pattern state, clock, or controls | only when simultaneous behavior must genuinely diverge |
| 8. More live renderers | full-frame blends and independent sources | only when shared material cannot create the picture |

## Track two different forms of multiplication

### Static multiplication

Unique Pattern instances may duplicate private bindings, source, and generated wrappers. Scene stacks, transition boundaries, routing, and capture logic may also be unrolled into the artifact. Only a few branches may run simultaneously while all of them still consume source or Controller image bytes.

Measure one unit, several exact repetitions, and several variations. The difference reveals fixed cost, unavoidable parameter cost, and accidental duplicated structure.

### Active multiplication

Count live Pattern evaluations per output pixel in holds and at the busiest transition. Count costly math inside those renderers separately. A small artifact can still be slow, and a large artifact can still run few sources at once.

## Identity rules

- Share an explicit Pattern instance across symmetric physical Zones and repeated Scenes when its private state, controls, and clock may agree.
- Use Effects, placement properties, phase, palette, address, routing, and physical dimensions to make shared material differ.
- Do not use unique IDs as scene labels or as a routine reset mechanism. If a restart is visually required, record why shared timing or placement scheduling cannot express it.
- For reference Shows, keep demonstration content neutral and shared so the demonstrated Effects or transitions own the budget.

## Boundary rules

- Prefer a Cut when the visual law changes abruptly and the boundary is not the subject.
- Use live/live blending only when simultaneous outgoing and incoming motion is visible and important.
- Prefer a shared transition family with compact parameters over many bespoke boundary implementations.
- Treat per-boundary artifact growth as a measured budget. A transition can be cheap at runtime yet too large to activate.

## Review questions

For every unique Pattern instance, name the independent visible state it owns. For every transition, name what the boundary contributes to the score. For every repeated Scene structure, show its artifact growth. For every extra live renderer, explain why transforms, masks, cached output, or snapshot policy cannot create the distinction.
