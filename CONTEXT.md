# PXLBLZ-IDE

A browser-based Pixelblaze authoring platform with a public Gallery, a cloud-backed Studio, hardware-faithful Pattern preview, reusable libraries and mixins, optional live Controller integration, and a Show system that compiles multi-Pattern choreography into ordinary Pixelblaze artifacts.

## Language

**PXLBLZ-IDE** (the product / this repo):
The product we build and ship, and the name of this repository — in **all** contexts, customer-facing and internal docs alike. Deliberately *not* spelled "Pixelblaze IDE": that is ElectroMage's own existing product, a name collision we avoid on purpose. The short wordmark **PXLBLZ** (used in the app shell and visual branding) is the same product; "the IDE" is acceptable shorthand in prose once context is clear, but the *name*, when named, is PXLBLZ-IDE.
_Avoid_: "Pixelblaze IDE", "Pixelblaze-v2", "pixelblaze-v2" (the old repo name being expunged). Saying "pixelblaze" aloud for our product is pronunciation convenience only — never write it that way.

**Pixelblaze**:
The spelled-out name (P-I-X-E-L-B-L-A-Z-E) is reserved **exclusively** for ElectroMage's things: the hardware LED controller it sells, its firmware, its pattern language, its own editor/software, and the broader ecosystem around them. Never our product.
_Note_: "**Pixelblaze V2**" (and V3 Standard/Pico) names a *hardware controller generation* — vendor terminology, unrelated to the old `pixelblaze-v2` repo name. Keep it verbatim in hardware/firmware/API docs.

**Pattern**:
A source file in Pixelblaze's JavaScript-derived language that runs on a controller; also the LED display that results from running it. Authored by the user.
_Avoid_: program (the websocket API's term), sketch, script.

**Library**:
A named collection of reusable global-scope functions and top-level state (the out-var contract: helpers that write shared globals like `ux`/`uy` for the caller to read immediately), referenced from Patterns as `Namespace.fn()`. Ordinary calls retain one runtime function call after the compiler flattens and mangles the reachable dependency graph. A single-return expression declared with `// @inline` also offers the explicit call-site form `Namespace.inline.fn()`: the compiler substitutes that expression, supports nested inline calls, retains reachable helper dependencies, and rejects arguments whose evaluation could be duplicated or reordered unsafely. The call site chooses the size/speed trade; the definition only declares eligibility. A library's top level holds only function declarations, `var` declarations, and comments — no executable statements. A library's name **is** its namespace: a single identifier-constrained field (case-sensitive, no spaces), unique across stock libraries, the user's own libraries, and **built-in** names. **Stock libraries** ship with the IDE (`SDF`, `Color`, `Anim`, `Coord`, `Noise`, `Shader`) and are read-only; **personal libraries** are user-owned and editable. References from Patterns are soft: nothing tracks which Patterns use a library — the name resolves at compile time, so renaming or deleting a library leaves dependent Patterns failing compile with an unknown-namespace error until their call sites are updated. A library's API documentation is generated from the `//` comments directly above each function declaration; eligible functions also expose their inline signature.
_Avoid_: module, package, import; separate display name vs namespace (they are one field).

**Built-in**:
A function or constant provided by the Pixelblaze runtime itself (`hsv`, `time`, `wave`, `sin`, `PI`, …) rather than by a library. Patterns call built-ins bare, without a namespace.
_Avoid_: native function, intrinsic.

**Control**:
An interactive preview-pane widget (slider, toggle, HSV/RGB picker) generated when a pattern exports a specially-named function (`sliderX`, `toggleX`, `hsvPickerX`, `rgbPickerX`). Its value is persisted per-pattern.
_Avoid_: input, knob, parameter, setting.
_Note_: distinct from **Controller** (the physical box). One letter apart, so never abbreviate — code and UI always spell out `control` vs `controller` (a "Controls" panel is the widgets; a "Controllers" list is the devices).

**Controller**:
A physical Pixelblaze reachable over the network via its WebSocket API (port 81, JSON + binary frames). The thing the IDE connects to, lists patterns from, pushes patterns to, and reads/writes variables and controls on. There may be more than one on a network, though typically one.
_Avoid_: device, board, unit, node — though the ElectroMage WebSocket API itself says "board," the IDE's canonical term is Controller. Never shorten to "control."

**Extension**:
A browser extension the user installs that lets the deployed (https) IDE reach a Controller. The page itself cannot open the Controller's `ws://` socket directly (mixed-content blocking), but the extension — running with elevated privileges outside the page's mixed-content sandbox — can, relaying frames between the IDE and the Controller, discovering Controllers through ElectroMage cloud discovery, and fetching the device compiler, `/pixelmap.dat`, and `/wifistatus` over HTTP on its behalf. Connection can start from a discovered row or **manual IP**; manual IP still works when discovery cannot identify the Controller, yielding a live but unclaimed connection. Optional, local-only, and purely additive — authoring/preview/export work with no extension installed. The IDE never launches the extension; the user installs it and the IDE detects it.
_Avoid_: server, backend, daemon, proxy, bridge, Node process — there is no separate process the user runs; it is a browser extension.

**Gallery**:
The public, signed-out-friendly surface at `/gallery` (also the landing page): a browsable grid of live animated cards for the built-in patterns, each linking to a **pattern detail page**. Each built-in directory also has a shareable filtered route at `/gallery/<directory-slug>`; changing the directory filter updates that route, while dimension and name filters remain local to the open page. Gallery cards are performance-bounded lower-density realizations of each Pattern's shared **recommended settings**; detail and Studio use that same familiar presentation without a Gallery-only multiplier. Gallery rendering is capped at 2,048 realized LEDs, including lattice rounding. The Gallery is the browse home for built-in patterns; personal patterns never appear in it.
_Avoid_: catalog as a synonym; calling it a store or marketplace.

**Studio**:
The signed-in working environment — the three-pane IDE at `/studio/...`, organized by the **left rail**'s six entity kinds. Gallery and Studio are a bright line: there are no special signed-out routes into the Studio; a signed-out visit is met by the welcome gate (GitHub/Google sign-in). Live Controller connectivity is orthogonal — it works on every route in every auth state.
_Avoid_: "the IDE" when the Gallery/Studio distinction matters; signed-out Studio variants.

**Documentation workspace**:
The public read-only surface at `/docs/<id>`. Its left catalog selects checked-in Markdown documents and its width-constrained reading canvas uses the repository's safe Markdown renderer. The header **Docs** button enters the workspace from Gallery or Studio; an explicit **Back** control returns to the exact route that opened it, and pressing the active Docs button remains a shortcut for the same action. Switching between Documentation and API Reference preserves that origin. It is not a Studio entity and never mounts or hydrates the Studio rail. Live Controller connectivity remains available in the global header.
_Avoid_: docs overlay, docs mode, treating repository documents as user-owned entities.

**API Reference**:
The public read-only library-documentation surface at `/reference/<library>`. It shows Pixelblaze built-ins and stock Library signatures/comments without presenting source as the primary content; entries use two columns when the reading canvas has room. When entered from Studio, it appends a **My libraries** group generated from the already-loaded cloud Libraries; an undocumented cloud Library remains listed with guidance to add `//` comments. Personal source is still edited only in Studio **Library mode**, reached through **Edit in Libraries**. Like Docs, an explicit **Back** control returns to the route that opened it, the active **API** button remains a return shortcut, and the global Controller surface remains available.
_Avoid_: Code area, library editor, implying cloud Libraries are public or that the reference surface edits source.

**Pattern detail page**:
A built-in pattern's shareable page at `/p/<slug>`: large live preview driven by the real engine, the pattern's exported controls, a Preview | Code toggle (read-only Monaco), **Open in Studio** for the read-only workspace/code view, and **Send to Controller** without entering the Studio. Cloning is deliberately a Studio action from that read-only view, not a Gallery action. Slugs exist for built-in patterns only.
_Avoid_: implying personal patterns have public detail pages (a later step).

**Device id**:
The stable identifier of one physical Pixelblaze, `pixelblaze_<boardType>_<reversed-mac-bytes>` — read directly from the device on connect (WS `getConfig` boardType + HTTP `/wifistatus` MAC), with cloud discovery as fallback, matching the id ElectroMage's discovery service reports. The hardware key for **Controller profiles**; IP is transport only, device name is display only. A live connection without a recoverable id is **unclaimed** — fully usable, just not auto-persisted.
_Avoid_: keying anything durable on IP or name; treating chipId or MAC alone as the id.

**Controller profile**:
The durable, D1-backed record of one physical **Controller** — claimed **device id**, board profile, hardware inputs, global transforms, **Controller power profile**, pattern bindings, zones, managed-artifact preference, and last-known hardware facts (device name, IP, firmware, firmware-update state, pixel count, and the last successful present/absent **installed-map observation**). Created from observed hardware, not from a blank manual form: signed-in sessions auto-create it when a live device reports a stable id, while an unclaimed live connection remains usable without becoming durable. The profile display name mirrors the mutable Pixelblaze device name whenever the device is seen again. Offline-editable at `/studio/controllers/<id>`; edits auto-save immediately and it holds durable configuration only, never duplicating live controls — those stay in the **Controller panel**. Its Map fact shows the live Controller observation while connected and otherwise resolves the saved fingerprint/dimension/point-count snapshot; a failed read never replaces the last successful snapshot. Its Firmware fact may show the last conclusive update state observed while the Controller was connected, read-only and still visible offline; the live panel remains the action surface. While the Controller is live, the profile route's right-hand context pane shows separate **Saved PXLBLZ Patterns** and **Other Patterns** inventories plus an opt-in to keep **managed saved artifacts** current. Other Patterns remain visible as Controller-owned content and are completely exempt from automatic writes.
_Avoid_: conflating it with the live connection or panel; "controller" bare when the profile/live distinction matters.

**Controller power profile**:
The optional installation-level power model inside a **Controller profile**: LED construction, continuous LED supply budget, and any measured, manufacturer-rated, or custom full-white load total. It preserves authored A/W units and assumptions, uses the Controller's last-known address count, and remains useful for telemetry whether or not a power cap is enabled.
_Avoid_: per-pixel current setting; power-cap configuration; treating an estimate as a measurement or a substitute for wire, fuse, injection, and supply design.

**Controller panel** (the connected-hardware surface):
A top-right-nav surface (icon → dropdown/popover) that **mirrors the live truth of a connected Controller** ("Model A"): its currently-running pattern, that pattern's **controls** and watched **vars**, its **brightness**, its reported **FPS**, its configured **pixel count** (live-editable — committing saves it to the device, the only way to make a fixed-size map apply), and its **installed-map observation**. The map value appears as name then one map-dimension pill, with the point count shown only when it disagrees with the panel's pixel count (an amber chip); a byte-exact profile or unique Studio match supplies the name, while a readable unmatched or ambiguous map is `Unknown map`. Loading, confirmed absence, and read failure remain distinct. Its header also carries device-wide **Play/Pause**, which freezes or resumes whatever Pattern is active, including foreign or otherwise unmanaged saved Patterns. Firmware exposes no authoritative paused-state readback. A fresh connection presents the Controller's normal running baseline, and a successful Pattern activation returns the control to playing because the push protocol ends by resuming the renderer; neither transition is presented as a command acknowledgement. A fresh positive FPS heartbeat can also present the renderer as playing; zero FPS presents a safe **Resume** action as "no render heartbeat" without claiming an authoritative pause. FPS is reacquired for every panel session rather than restored with the panel's other cached live values. Acknowledged Play/Pause commands remain authoritative. A small local recovery marker survives disconnect/reload when PXLBLZ may have left a Controller paused; acknowledged Resume or successful Pattern activation clears it. The control otherwise becomes unknown when connection ownership is lost and always leaves an explicit **Resume** recovery path; it never claims to know about commands from another client. The panel also carries a quiet firmware reminder when the Controller's own update service reports a compatible release: a separate amber pill icon plus a compact panel link to the Pixelblaze web UI's Settings → Updates flow. PXLBLZ never compares release versions or installs firmware. Structured to echo the preview deck's control vocabulary, but bound to the *Controller's* state, never to the editor buffer — the two surfaces are linked only by **Send to Controller**. Some fields are live-editable (brightness, controls); **brightness is editable only here** and never inherited from the preview, because physical LEDs are far brighter than a monitor (preview brightness is the wrong value for a strip). Power draw estimates use live brightness and pixel count with the **Controller power profile**, report both amps and watts when voltage is known, and disclose whether the load is estimated or overridden. Optimized for one connected Controller though it supports several. Absent/empty when no **extension** or Controller is present.
_Avoid_: "device panel" (Controller is canonical); treating it as a second editor — it monitors/commands a Controller, it does not author.

**Installed-map observation**:
The connection-owned fact produced by one raw `/pixelmap.dat` round trip for one **Controller**. It is loading, present, absent, or failed. A present observation retains the exact bytes and derives fingerprint, dimension, and point count from that same blob; identity resolution is separate and can improve when profile history or personal maps load without reading hardware again. Signed-in Controller profiles persist only the last successful present/absent snapshot, never a failed read or copied map record. The observation, not map push history, is live installed-map truth for the Controller panel, Controller profile, map import, renderer compatibility, and Show preparation.
_Avoid_: treating the most recent map push as proof of what firmware installed; calling a failed read an absent map; persisting the raw map blob in the profile.

**Send to Controller** (the push action):
The grouped Controller identity plus direct **Run** and **Save** actions that send the open **Pattern** or compiled **Show** to one Controller. **Run** is transient and does not enter Saved Patterns; **Save** persists and activates the artifact. The actions are enabled only when a Controller is connected and the artifact compiles cleanly, with cross-dimensional renderer adaptation, firmware warnings, and known incompatibility surfaced before send. Pattern sends use the normal bundled artifact or a pass-engine derivative from the active **Controller profile**. Show sends preserve the canonical Show provenance and output contract while applying any required Controller derivative. The dirty gate tracks each source and Controller-affecting derivative independently for Run and Save. A clean Run remains inert only while the Controller is known to be running that exact transient artifact; observing another active Pattern re-arms Run without requiring a source edit. Save cleanliness is independent of the active Pattern. *Nothing from Pattern preview presentation rides along*: not its selected map, brightness, fit (Fill/Contain), pixel count, speed, light size, diffusion, solidity, fidelity, layout, or live control values. Source changes still require a deliberate user push. A separately authorized Controller-profile reconciler may refresh only **managed saved artifacts** after code-affecting hardware settings change. **Save** uses overwrite-in-place: the IDE remembers a per-Controller binding from Pattern, demo, or Show identity to the Controller-assigned id, so repeated saves update one stored program rather than piling up copies. **Run** uses throwaway ids and does not affect that binding. Control values are tuned live afterward in the **Controller panel**.
_Avoid_: "deploy" or "upload" as the canonical verb (the verb is push / Send to Controller).

**Push record**:
Durable IDE-side metadata written after each successful **Save** push, keyed by
the same `(Controller, IDE Pattern/demo/Show)` pair as the overwrite binding. It
copies the exact artifact banner facts embedded in the saved PBP — transforms,
artifact hash, stamp time, pushed name, and any **Show output contract** — and
overwrites the previous record on re-push. **Run** pushes never create records.
The record makes transform freshness and saved-Show output facts locally
computable without reading Pattern source back from hardware.

**Managed saved artifact**:
An installed Controller program eligible for PXLBLZ's opt-in automatic derivative reconciliation. Eligibility requires three independent facts: a PXLBLZ overwrite binding to that exact Controller program id, a successful **push record**, and regenerable Studio source for the bound Pattern, demo, or Show. Reconciliation overwrites the same id with current Controller-profile transforms and renderer adaptation, without activating each program in sequence. Missing bindings, missing push records, missing source, foreign programs, and programs deleted from the Controller are unmanaged: PXLBLZ never modifies, recreates, renames, or deletes them automatically.
_Avoid_: treating every binding-owned row or every stamped Controller program as managed; describing the opt-in as ownership of the complete Controller.

**Transpiled artifact** (or **artifact**):
The single flat JavaScript file the transpiler produces for a Pattern — reachable ordinary library functions flattened and renamed, explicit inline-library calls expanded, and namespace calls rewritten. Valid for both browser preview and hardware upload. The downloadable/copyable output.
_Avoid_: bundle (the verb is fine; the noun is the artifact), build, output file.

**Transpiler**:
The engine component that turns Pattern source into a transpiled artifact: it parses with Acorn, resolves Library references (including transitive cross-library ones), tree-shakes to only referenced functions, mangles ordinary function names, and expands explicitly selected `Namespace.inline.fn()` expressions. It emits only top-level Library `var` declarators reachable from the selected function graph, their initializers, or the Pattern's bare out-var reads. Those globals remain unmangled and precede emitted functions. Returns `{ code, fxCode, metadata }`.

**Pass recipe**:
A JSON-serializable instruction list that asks the pass engine to derive a hardware artifact from source without editing the user's pattern. Recipes are produced by Controller profiles, renderer compatibility, and Shows, then applied in order at Send to Controller or Show compile time. Current pass kinds cover source injection, output interception, input-to-target binding, and exact-arity renderer adaptation; the resulting generated artifact is inspectable, but the recipe is the durable user intent.
_Avoid_: calling a pass recipe source code; storing generated helper names as user-authored configuration.

**Transform summary**:
The inspectable report emitted with a pass-engine-generated artifact: pass list, warnings, inserted globals/exports, `beforeRender` work, rewritten output call sites, bindings, renderer adapters, and rough cost notes. Controller profiles and mixin provenance panes show the latest summary with a read-only generated-artifact viewer. Warnings about missing sinks, missing inputs, missing binding targets, or an impossible renderer-adapter name belong here.
_Avoid_: treating the summary as editable source or implying it is sent to hardware.

**Var watcher**:
The preview-pane table showing the live values of a pattern's `export var` globals, sampled after each rendered frame.

**Left rail**:
The app's object browser and primary open/select surface. Its top-level organization follows **object type** before provenance: **Patterns**, **Shows**, **Maps**, **Controllers**, **Mixins**, and **Libraries** live as rail modes in that order; the public **Gallery** remains a separate top-bar destination. Every personal entity kind uses a recursive, manually ordered folder tree whose sidecar references stable entity IDs and never becomes entity identity. The mutable tree begins immediately under the one entity header, whose action menu owns creation and import commands; only a Built-in provenance boundary remains labeled where curated content exists. Personal nodes move through whole-row drag and drop or explicit menu commands. **Trash** stays hidden while empty, preserves recoverable nodes and folder subtrees, and permanently deletes their records only through **Empty Trash**. Built-in trees reuse the row and disclosure grammar but remain immutable. **Controllers** lists durable hardware profiles by their last observed Controller names, has no Built-in section, and offers no blank-new or profile-rename affordance. The compact **dimension lens** belongs to dimensional authoring content (Patterns and Maps); name search also covers Shows and matches nested folder paths. Switching rail mode restores that mode's last selected/open destination where possible. The active entity header owns the **Collapse library** action; the 46-pixel collapsed activity strip owns **Expand library**.
_Avoid_: treating **patterns**, **maps**, and **controllers** as one interchangeable saved-item list; putting all user-owned objects together just because they share provenance.

**Personal content provider**:
The storage seam behind personal **Patterns**, **Maps**, **Mixins**, **Libraries**, **Shows**, durable **Controller profiles**, and their settings/metadata. Durable personal resources have one supported backend: authenticated Cloudflare Pages Functions backed by D1. Signed-out users run in non-durable **demo mode**, where built-in demos, stock maps, stock mixins, libraries, docs, preview controls, and live Controller connectivity remain usable but personal create/update/delete actions require sign-in. The remote provider stores personal Patterns, custom maps, personal Mixins, personal Libraries, Shows, Controller profiles, last-active state, demo overrides, organization sidecars for all six personal entity kinds, and Controller push metadata through authenticated Pages Functions. No browser-local-to-D1 migration is attempted. The Cloudflare D1 binding (`PXLBLZ_DB`) and OAuth/session foundation sit behind this seam so React components do not know about D1, Workers, or auth.
_Avoid_: implying multiple personal stores are visible at once; wiring database or network details directly into UI components; describing a durable signed-out workspace.

**Active document**:
The single file currently open in the editor — exactly one **Pattern**, **demo**, **Library**, **custom map**, **stock map**, **personal Mixin**, or **stock Mixin** at a time. PXLBLZ-IDE deliberately remains a single-document editor in this slice: no editor tabs, no background-open buffers, and no recent-document stack. Opening a document is an active operation: a Pattern/demo changes the running preview Pattern; a map opens source in **map mode** without assigning that map to the current Pattern; a Mixin opens source in **Mixin mode** without applying it to any Controller or Show. Any future "recent documents" affordance should be a reopen shortcut that performs the same action as selecting the item in the **left rail**, not a tab model.
_Avoid_: implying multiple files can be open concurrently; treating document navigation as editor-only when it also changes preview context.

**Clone**:
The user action that turns a read-only stock object into an editable user-owned copy: a **demo** becomes a personal Pattern, a **stock map** becomes a custom map, a **stock Mixin** becomes a personal Mixin, and a **stock Library** becomes a personal Library under a fresh identifier-safe namespace (for example `SDF2`), never the stock name. A clone is a separate Library, not an override; wrapping, where a personal Library calls stock functions, is the escape hatch for tweaking stock behavior. The source and settings copied depend on the object type, but the user-facing verb is the same because the intent is the same: preserve the shipped original and start editing your own version.
_Avoid_: "Edit" for this action when it could imply mutating the read-only original; using separate verbs for demos and stock maps unless the behavior truly differs.

**Installation**:
The physical LED system a Show may target: pixel count, wiring/index order, electrical construction and supply, spatial topology and map, Controller zone ranges, and the surfaces or volumes those pixels occupy. An **installation-bound** Show or effect relies on some exact part of that arrangement; an **adaptive** one instead declares a dimensional, topology, and aspect-ratio compatibility contract and can be re-evaluated at other supported resolutions. Installation is not a synonym for Controller, map, Stage, or Show: each describes one part or representation of the physical work.
_Avoid_: calling arbitrary preview geometry an installation; assuming resolution independence also guarantees topology or aspect-ratio independence.

**Pixel map** (or **map**):
An ordered coordinate set for an LED installation — list position is the LED **index**, and each point carries the value(s) the Pattern samples. A true 1D map carries `[x]` and may deliberately virtualize chain progress without claiming a physical embedding; 2D/3D maps commonly carry the installation's spatial coordinates as well. Workspace-owned and selectable per Pattern (a Controller is an optional downstream consumer, not a prerequisite). A uniform grid is the simplest map, not a separate concept.
_Avoid_: geometry, coordinate set, pixel mapping. (Not "layout" as a bare synonym; see **Layout**.)

**Geometry family / coordinate view**:
A generated physical point set catalogued once, with one or more honest map-coordinate views over the same LED indexes. The geometry family owns preview `pos`; the selected coordinate view owns hardware-real `sample` and materializes as an ordinary self-contained Pixelblaze map source. **Strand** `[x]` is deterministic wire progress, **Surface** `[u,v]` is offered only for an intentional generator-owned parameterization, and **Spatial** `[x,y,z]` is the generator's normalized physical position. Switching views never moves the preview points. Cylinder ships all three; Square/Wide/panel grids ship Strand + Surface; generated Cube/Sphere/Star/Tetra shell and volume distributions ship Strand + Spatial. Shell and volume siblings remain separate families because they are different point sets. Ring remains an honest planar 2D Path without invented UV/XYZ siblings, and measured Sunflower maps remain Custom/imported single coordinate sets.
_Avoid_: listing a family's views as unrelated geometries; calling a coordinate view a preview-only embedding; treating shell and volume as views of one point distribution.

**Map catalogue taxonomy**:
The explicit physical classification carried by every catalogue entry: **Path** (ordered curve), **Surface** (parameterized sheet/wall), **Shell** (boundary distribution), **Volume** (filled interior), or **Custom / imported** (authored or measured coordinates without a generator-owned physical claim). It is independent of ownership: Cloud versus Stock remains the primary rail split, while both the Maps rail and Pattern Map menu use the same taxonomy for scanning. Empty categories disappear. A geometry family occupies one catalogue item with nested coordinate views.
_Avoid_: inferring type from an id/name suffix; treating a stock measured coordinate array as generator-owned geometry; merging shell and volume because both use XYZ.

**Layout** (the preview's two-control selection):
Collective term for *the spatial arrangement chosen for the preview*, now split across **two orthogonal controls** rather than one union dropdown:
- the **Map** control — owns `sample`; offers every map dimension to every Pattern. Choices matching the Pattern's native dimension appear under **Recommended**; **Other dimensions** holds the rest. **Index** is the reversible no-installed-map 1D view (`x = index / pixelCount`). An internal **Auto** sentinel chooses the first Recommended option for an untouched Pattern and is never shown or persisted as a map entity.
- a generated family's subordinate **View** control — changes which ordinary map source supplies `sample` while retaining the family's physical `pos`. It appears only when the selected family has alternate coordinate views.
- the **embedding** control — owns `pos`; populated from the selected **map dimension**, not Pattern dimensionality: visible as **Shape** for Index/1D, **Display** with Flat/Cylinder wrap for 2D, and trivial (identity) for 3D. Present whenever there is a display choice to make.
The earlier single "Layout dropdown" union is **retired** (it conflated `sample` selection with `pos` selection; the §**Sample / position** split now has one control each). "Layout" survives only as this collective noun; elsewhere it stays a forbidden synonym for **map**.
_Avoid_: "the Layout dropdown" (there are two controls now — say the **Map** control or the **embedding** control); using "layout" to mean a **map** specifically (say map).

**Resolved layout**:
The *drawn realization* of a **Layout** selection — what `resolveLayout` (`src/engine/layout.ts`) produces from the selection plus the Pattern's native dimensionality, the modeled pixel count, and the **normalize** mode. Distinct from the *selection* (the persisted `mapId`/`shapeId`/`surfaceId`): the resolved layout is the corrected selection **plus** the selected **map dimension**, per-index `sample`+`pos` (**map points**), modeled `pixelCount`, **display** dimension, grid readout label, and draw channel — a 2D position list, or a 3D position list with optional solid-eligible **surface normals** (`normals !== null` *is* the **solidity** eligibility). It is the single seam the preview's render effect consumes: the component writes the corrected selection back to the store and feeds the rest to the renderer/render loop, holding no layout logic itself. The resolver is engine-pure (no store/React import) — its store-coupled lookups (`resolveMap`, `mapGridDims`, the per-dimension default count) are **injected** as `deps`, which is also what makes every branch (line/ring/pole shape, plane, 2D cloud, cube, shell, cylinder-wrap) table-testable with fake maps.
_Avoid_: conflating it with the **Layout** *selection* (one is the chosen ids, the other the drawn points/normals); "resolved map" (a **map** resolves to **map points**; the resolved *layout* also folds in the embedding, count, normals, and label).

**Preview resolution**:
The Preview-only convenience control for changing modeled pixel count through a short, geometry-aware ladder while retaining exact count entry. Square, Wide, and Cube expose natural complete-grid stops; regenerating non-grid geometry uses a bounded generic ladder; a custom baked map exposes exact count only. A stock literal coordinate array instead exposes its authoritative authored count as a locked readout. Quick stops end at 2,048 LEDs, but exact entry may exceed that ceiling. An exact value between stops is shown with the same indeterminate slider treatment used while live Controller values are unresolved; minus/plus move to the adjacent natural stop. This is exploratory Preview behavior and persists through the ordinary **settings cascade**. The **Controller panel** deliberately keeps only exact entry plus an explicit hardware write.
_Avoid_: treating the 2,048 quick-selection ceiling as a renderer or hardware limit; adding a continuously scrubbable Controller pixel-count slider.

**Stock map**:
A **map** that ships with the IDE — selectable in the preview, revealable in the **Maps** rail, openable read-only in **map mode** at `/studio/maps/<stock-id>` as an example to learn from, cloneable into a new **custom map**, pushable directly to a **Controller**, but never listed in **Cloud Maps** and never deletable. The defining axis is *provenance* (ships with the IDE), analogous to how a **demo** is a stock, read-only pattern. Every stock map is backed by real plain-JS map source (either a `function(pixelCount)` returning a coordinate array or a literal coordinate array for measured hardware) which is **the single source of truth** the preview runs (via `new Function`, float64, no fixed-point shim). Function stock maps **regenerate live** for any count; literal-array stock maps intentionally keep their measured point count, so the baked-replay mechanism is still reserved for **custom maps** only. The source is **hardware-Mapper-faithful and self-contained**: it reads like code you could paste into a real Pixelblaze Mapper tab (`Math.*` and language built-ins only for functions, no IDE helpers or **libraries**), returns or directly provides **raw geometry**, and the engine applies the shared aspect-preserving **normalization** pass. Opening a stock map shows this source read-only; **Clone** copies the source into a new **custom map**. Every stock map is source-backed. Stock maps now span 1D/2D/3D through generated coordinate views; 1D **shapes** and the Flat/Cylinder viewport **surfaces** remain independent preview embeddings for ordinary maps.
_Avoid_: built-in map (collides with **Built-in**, reserved for runtime functions/constants); default map (ambiguous with the auto-picked-on-open map).

**Stage**:
The preview place a **Show** renders its zones onto. Every Show's **output contract** supplies the Stage map: a Portable Show uses its editable reference map/count, while an Installation Show uses its exact output map and master pixel count. The right pane presents Stage and coverage facts as read-only output context; Show creation and Show properties own durable or reference choices. The Stage remains preview geometry for authoring and debugging: imported Controller maps are natural Installation stages because their frozen pixel indexes line up with physical-zone ranges. Portable Stage ownership is recalculated from each map point's normalized position and never borrows Controller ranges. Aspect-preserving maps warn when a logical boundary uses a compressed coordinate axis. Spatial stages warn when a zone has no pixels on the selected map and draw uncovered Stage pixels dim grey; generic strips are intentionally geometry-free and never warn.
_Avoid_: treating Stage as a map association on a Pattern or scene; changing a saved output map from the right pane; saying a Stage changes what source Patterns read (Shows are routed by index; the Stage is the drawn place).

**Zone**:
A named semantic subset of a Show's output. A logical zone expresses normalized choreography without claiming LED identities. An Installation physical zone owns one or more inclusive index ranges within the Show's master pixel count; every physical **Zone Layout** must assign each output index exactly once. Controller zones are separate durable hardware setup that a later compatibility check may compare with the Show. Patterns stay zone-ignorant - routing and clipping happen in the Show/pass recipe layer.
_Avoid_: assuming a zone must be contiguous; treating a zone as a hardware port or a second map.

**Zone Layout**:
A reusable named definition that partitions one Show's complete output among its zones. An Installation Zone Layout assigns physical pixel ranges; a Portable Zone Layout pairs an ordered set of zones with a normalized **Stage-space routing operator**. The unified Timeline is divided into explicit **Zone Layout intervals**; each interval references one definition and restates the visible Zone/Layer stack at its boundary. `Full Stage` is the ordinary one-zone layout used when one Pattern should cover the complete output between multi-zone intervals. A layout change reassigns output ownership but does not itself choose Continue or Restart; **Pattern instance** lifecycle remains explicit Clip behavior. The editor may focus or collapse Zones without opening another editing scope. Internal code and technical references may retain `routingLayout` and Scene-partition names for the compiled representation.
_Avoid_: zone set, routing layout in user-facing copy, or bare layout when Zone Layout is meant; treating a Zone Layout as the Stage map or allowing one clip to escape its selected zone.

**Stage-space routing operator**:
The normalized 2D ownership rule inside a Portable **Zone Layout**. A hard operator returns exactly one zone plus normalized coordinates inside that region. **Soft Split** instead returns a continuous weight between exactly two zones: outside its feather only one Pattern renders, while the feather blends both. Full Stage, Grid, Stripes, Checker, Rings, Pinwheel, Wave, Moving Split, and Soft Split share this canonical model. Shape parameters are static Zone Layout configuration; Moving Split and Soft Split position appear as ordinary owned Property animation on the unified Timeline. The compiler lowers operators to direct scalar coordinate formulas with no pixel-count-sized routing table. Rings and Pinwheel use normalized radial geometry and surface an aspect advisory on strongly non-square Stage maps.
_Avoid_: calling an operator a map or Effect; treating Soft Split as overlapping physical zones; assuming a Portable operator depends on pixel index or wiring order.

**Scene** (in a Show):
A persisted compatibility and compiler interval spanning the complete Show rather than one Zone row. A Scene selects one **Zone Layout**, owns Show-wide property targets, and meets its neighbors at stable **Transition** boundaries. The unified editor does not expose Scene as an authoring object: it resolves direct Clip time, Layer, and Zone edits onto internal Scene owners. Clips may preserve a **Pattern instance** across an internal boundary.
_Avoid_: using Scene in production labels, help, diagnostics, or exported summaries; using scene for one zone's clip; treating each zone row as an independent Scene; nesting Scenes inside Scenes.

**Zone composition** (internal Show representation):
The compatibility/compiler partition for exactly one internal **Scene** x **Zone** cell. It stores the bottom-Layer Clip schedule, higher Layers, and typed Property animation tracks before lowering. The production editor projects these partitions into continuous Zone and Layer rows on the unified Timeline; it never opens a Zone-composition sub-editor.
_Avoid_: presenting Zone composition as an authoring scope; recursive timelines; cross-Zone Clips.

**Main clips** (internal storage term):
The persisted schedule that projects as the bottom Layer of one Zone. Its Clips are mutually exclusive in time, may leave intentional gaps, and render beneath higher Layers. The production editor treats it as a normal Layer except for its stable bottom position.
_Avoid_: Base Cuts; assuming the Layer must cover the whole Show; treating Main as a special Pattern type.

**Overlay layer**:
A manually ordered compositing Layer above the bottom Layer in one Zone. One Layer may contain several non-overlapping Clips; Clips in different Layers may overlap in time. The top Layer is visually in front. A Clip belongs to one Zone and does not draw outside that Zone.
_Avoid_: creating one Layer per Clip; assigning Layers automatically by Zone; treating Stage diagnostic outlines as spatial editing handles.

**Show output contract**:
The versioned promise every **Show** chooses before its timeline opens. Its kind is immutable: an **Installation** contract owns one fixed pixel count and output map for a known physical build, while a **Portable 2D** contract promises resolution-independent choreography across compatible 2D mapped surfaces. Compiled Show output supports at most 2,000 pixels. Installation counts and Portable reference counts stop at that ceiling; a Portable artifact is eligible only when its target Controller also reports at most 2,000 pixels. Portable's editable reference map and count make authoring concrete without becoming exact LED identity or changing the promise. Portable zones use normalized Stage-position predicates, never physical ranges or Controller-zone bindings. Member Patterns must expose `render2D` or adaptable `render`; 3D-only members and non-2D references block artifact output rather than weakening the promise. The canonical generated artifact carries the same contract in its PXLBLZ banner: Installation includes exact count and map identity/fingerprint when available, while Portable includes compatibility facts but deliberately omits reference count and map as requirements. EPE import, Controller read-back, renderer adapters, and saved-program inventory preserve that record. The stored discriminant is `installation` or `portable-2d`; display copy does not determine persistence. Rows without a valid output contract are rejected instead of being classified from unrelated saved fields.
_Avoid_: treating the contract as a temporary Preview setting; inferring portability from map dimension; implying an existing Show can convert between contracts.

**Show**:
A saved choreography under one **Show output contract**. Its canonical editor is one proportional timeline of direct **Clips** on explicit **Layers** and **Zones** under a shared ruler. Clip Start fields use Show-global time. A boundary that needs a name uses the primary incoming Clip's compact identity: `15.0: CompassRose` below one minute, `1:15.3: CompassRose` at or above it, plus an additional-Clip count when needed. Internal Scenes remain a persistence and compiler partition, not an authoring object. Stable first-class **Transition** entities sit at junctions between connected Clips on one Layer. Cut, crossfade, Fade through color, wipe, dither, and portal select independently of either neighboring Clip; even a zero-duration Cut remains an explicit selectable junction. A Clip references a Pattern/demo through one **Pattern instance**, occupies one time interval on exactly one Zone and Layer, and owns placement, Effects, and presentation. **Live** presents the running Pattern, **Freeze** captures one complete RGB traversal at Clip entry, and **Strobe** periodically captures and holds complete traversals. **Blink** gates the final Clip output without stopping its Pattern clock. Advanced evaluation policies remain separate: authored **Freeze at entry** and **Refresh (4 slices)** reduce Pattern work while keeping private time alive. Splitting a Clip preserves its Pattern instance; **Make Pattern Independent** clones the instance and its local automation for one Clip, while **Rejoin Shared Pattern** deliberately adopts another compatible instance and discards an otherwise orphaned private instance. A Clip may be deleted to leave explicit blank time. A Clip-level property target belongs to its destination Clip; a Show-wide property target belongs to its internal destination Scene. In both cases the incoming junction owns how an explicit start reaches the target over that property's duration and easing. Nested Animation speed, Brightness, Pattern-control, and Split bands are projections of the same property-transition model; multiple independent curves may run together, including exact-zero pause and moving Zone ownership without private-clock reset. Pattern controls mean exported slider functions only, never arbitrary private locals. The Show compiler turns the arrangement into one generated Pixelblaze artifact routed over Controller Zones or the saved Stage. Shows own their output promise, transport, timing, placement, Zone routing, Clip adaptation, and **Show output Effects** so Patterns remain reusable textures. New timeline compositions reset Pattern state and clocks at the explicit Show End so every loop is deterministic. Preview seeking reconstructs that same deterministic Pattern state from Show start; Trails deliberately clears only its prior-frame output history at the destination and does not mutate the saved Show.
_Avoid_: playlist when describing compiled multi-zone choreography; implying patterns know which zone they are rendering.

**Group definition** (in a Show):
Zone-agnostic reusable choreography containing relative-time Clips, relative Layer offsets, complete non-Cut Transition chains, Clip Effects, Property animation, and an internal Pattern-instance sharing graph. A definition never contains another Group, a global Marker, a Show output Effect, or a Zone Layout boundary. Editing a definition updates every linked **Group occurrence** unless the active occurrence first uses **Make Unique**.
_Avoid_: treating a Group definition as a rendered Pattern, a Zone, or one placement on the timeline; nesting Groups; placing only one endpoint of a Transition in a Group.

**Group occurrence** (in a Show):
One Scene-interval- and Zone-local placement of a **Group definition**. It owns Show start, base Layer, destination Zone, and normalized X/Y translation. Linked occurrences share choreography but project fresh occurrence-local Pattern runtime identities while preserving the definition's internal sharing graph. **Duplicate** creates another linked occurrence, **Make Unique** copies the definition for one occurrence while keeping its container, and **Ungroup** materializes ordinary Clips and removes only that occurrence's container.
_Avoid_: sharing private Pattern state between Group occurrences; allowing an occurrence to cross a Zone or Zone Layout boundary; using Ungroup when the intent is to keep the container and unlink it.

**Show score** (compiler detail):
A compact runtime table for compatible repeated choreography. It stores five words per boundary - outgoing stack, incoming stack, Transition kernel, easing, and duration - while each unique Pattern instance, Scene-stack renderer, and Transition kernel is emitted once. `beforeRender` interprets the score and writes the active configuration; the pixel renderer dispatches only across interned stacks and kernels, so Scene count does not multiply per-pixel machinery. Pattern identity, private state, Controls, clocks, evaluation policy, and authored boundary identity remain unchanged. Score words are ordinary interned-plan memory and do not consume the three-plane render target. Incompatible Show structures retain the exact unrolled emitter.
_Avoid_: calling the score a frame buffer; merging Pattern instances because their source matches; moving score interpretation into the per-pixel renderer; claiming smaller source as an FPS gain.

**Show VM resource ledger**:
The compile-time inventory that decides whether one complete Show fits the Pixelblaze virtual machine before artifact actions become available. It accounts for arrays as words, including each four-word array header, and keeps member Pattern arrays, compiler routing tables, interned plan tables, auxiliary caches, persistent globals, and artifact bytes on explicit axes. The compiler reserves three RGB render-target planes for the Show's supported output extent: `3 * (pixelCount + 4)` words, or exactly 6,012 words at 2,000 pixels. That leaves 4,228 of the 10,240 array words for the complete Show, not for each Pattern instance. Literal arrays, `array(pixelCount)`, and provable constant sizes receive exact ownership; an unprovable size blocks artifact actions and names the Pattern plus a repair. Preview does not consume this eligibility decision and stays available for diagnosis.
_Avoid_: framebuffer budget when referring only to member arrays; treating the 4,228 residual as a per-Pattern allowance; assuming a previewable Show is necessarily hardware-eligible.

**Show render target**:
The compiler-owned arena of exactly three full-output Pixelblaze arrays emitted into every generated Show. The same physical planes may serve one typed role at a time: RGB Stage output maps `r/g/b` to planes `0/1/2`, sample coordinates map `x/y` to `0/1`, a scalar field maps `value` to `0`, and previous RGB maps `r/g/b` to `0/1/2`. A role names how generated code reads and writes the planes; it does not allocate another buffer. Snapshot/live Crossfade assigns `stage-rgb` while its outgoing composite remains valid; Trails assigns `previous-rgb` for ordinary output frames. A required Transition snapshot may temporarily take the same planes because Trails suspends, clears, and reseeds after that boundary. Direct rendering with neither policy leaves the arena unassigned. Installation allocates at its fixed count; Portable allocates at the supported 2,000-pixel ceiling.
_Avoid_: implying each role owns separate arrays; treating an unassigned arena as a captured frame; adding a fourth compiler-owned full-output plane.

**Show render-target plan**:
The compiler's deterministic schedule for sharing the three physical render-target planes. Every candidate declares its stored value, required plane count, lifetime, invalidation boundary, exactness, setup/replay cost, expected reuse, and explicit conflicts. Required authored policies are considered first; exact optional caches outrank approximate optional caches, and stable candidate ids break remaining ties. Overlapping assignments receive disjoint planes, while non-overlapping assignments may reuse the same plane numbers. One authored exception allows Show-lifetime `previous-rgb` Trails and a required Transition `rgb-snapshot` to bind the same planes because the generated Trails policy suspends and clears its history for the complete Transition lifetime. Other overlapping three-plane policies still conflict. Rejected candidates retain uncached behavior and explain whether they were unauthored, unprofitable, conflicting, or unable to fit. The plan allocates no arrays beyond the Show render target.
_Avoid_: treating estimated work units as measured FPS; allowing an emitter to claim planes outside the plan; assuming every profitable candidate can coexist.

**Scalar visual field** (compiler detail):
One exact scalar value per physical output pixel, derived from explicitly named producer semantics in one coordinate domain and reused by compatible Pattern or Effect consumers. The field contract names its producer identity, coordinate-domain key, lifetime, invalidators, exactness, expected frame count, and consumers before it becomes a render-target candidate. A selected field lazily writes its first complete frame into one planner-assigned arena plane; later frames read that plane until ownership or geometry changes. Non-overlapping fields may reuse the same plane through distinct owner generations. The initial producer is the frame-stable coherent-noise geometry behind spatial Dissolve Transitions in direct, Scene-sequence, and routed Shows.
_Avoid_: treating visually similar geometry as identical; reading a field in another map or Zone-local domain; claiming a planner work estimate as measured FPS; allocating a separate field array outside the three-plane arena.

**Sample-coordinate field** (compiler diagnostic):
One exact transformed X/Y pair per physical output pixel, produced for a named map/sample domain, complete static Scene transform, control identity, lifetime, and invalidation key. A diagnostic candidate may lazily fill planner-assigned `sample-xy` planes on the first Scene frame and replay them until the Scene changes. Incompatible maps, transforms, controls, or lifetimes remain direct. The firmware-3.67 pb32 qualification found no repeatable gain and a repeatable 6.43% median loss at 2,000 pixels, so production does not emit this cache; the contract, planner decision, exact counterfactual emitter, and benchmark remain available for future hardware profiles.
_Avoid_: calling a profitable work estimate a runtime win; enabling coordinate replay without a positive Controller profile; allocating separate X/Y arrays; confusing cached Pattern samples with preview `pos` geometry.

**Shared Pattern output** (compiler detail):
One exact RGB evaluation of a Pattern instance over a local sample domain, materialized once per frame and replayed by compatible placements. Compatibility requires the same Pattern source and instance, clock and inputs, property values, local coordinate/sample domain, selected render function, pre-cache Effects, and render-pure state. Consumer-only composition such as opacity remains after the cache boundary. Equal-size physical Zones may share because their local indexes and pixel counts are identical even when their Stage ranges differ. The planner selects sharing only when estimated Pattern work exceeds capture and replay cost; rejected, stateful, unknown, or incompatible consumers retain independent rendering. Shared output binds `stage-rgb` to the existing Show render target and allocates no additional arrays.
_Avoid_: treating source identity alone as compatibility; sharing a renderer that mutates state; confusing one cached output with merged Pattern instances or clocks; claiming estimated work as measured FPS.

**Snapshot/live Crossfade**:
The recommended Crossfade policy for newly authored boundaries. Its first transition frame captures the complete outgoing Stage composite into the Show render target while rendering the incoming side live. Later transition frames replay that frozen outgoing RGB and render only the incoming side. Readiness invalidates when the boundary exits or the Show loop re-enters it. The alternative **live/live Crossfade** evaluates both changing sides throughout the boundary; legacy Crossfades with no stored policy retain that behavior.
_Avoid_: describing the snapshot as exact live continuation; freezing an explicitly live/live boundary; conflating skipped pixel rendering with a stopped Pattern clock.

**Pattern instance** (in a Show):
One logical runtime identity for a Pattern's private state, clock, exported controls, time scale and offset, Stutter policy, and authored evaluation policy. Several Clips may reference one instance, including Clips separated by gaps or placed in different Layers or Zones; they observe the same state and clock without duplicating the Pattern source body. **Stutter** quantizes that shared clock into authored time steps, so every linked Clip sees the same stepped time. **Make Pattern Independent** clones the current instance settings and local automation for one Clip. **Rejoin Shared Pattern** points that Clip at another instance of the same Pattern and removes its old instance-owned settings and automation when nothing else uses them. Live, Freeze at entry, and four-slice Refresh change how an instance's pixels are evaluated; Clip-level Freeze, Strobe, and Blink change one placement's presentation. Neither set of policies silently changes identity. The compiler may still assign non-overlapping logical instances to one physical Pattern machine by restoring compiler-owned state banks at interval entry; this storage reuse never merges logical identity. Zone Layout changes determine where output is routed, not how many Pattern instances exist.
_Avoid_: equating instance with clip, placement, Scene, zone, or emitted machine; assuming repeated visual placement always duplicates source; sharing logical identity whose clocks or private state must diverge.

**Shared transition kernel** (compiler detail):
One generated transition body reused by boundaries that have the same visual-stack structure and transition policy. The scheduler writes the few changing scalar parameters, while the kernel owns the invariant routing, sampling, and composition environment. Sharing generated code does not merge Pattern instances, clocks, or authored boundary entities. The compiler selects it only when the emitted representation is smaller and exact in both Fast and Precise execution; incompatible sequences retain unrolled boundary code.
_Avoid_: Pattern-instance reuse; caching a rendered frame; assuming smaller source implies faster rendering.

**Built-in Show**:
A session-editable Show example that ships with the IDE and opens through the same timeline, Stage, compiler, cost disclosure, generated-code view, EPE export, and Controller-send paths as a personal Show. The pristine choreography remains an ordinary `ShowRecord` fixture. The first edit creates an in-memory working copy with normal Undo/Redo; **Reset** or a page reload restores the fixture, and no edit seeds D1 or creates an undeletable personal record. Built-in Shows are organized as numbered **Learn** lessons, topical **Showcases**, and **Remixes** — finished pieces scored over community Patterns; catalogue-only metadata supplies their order, lesson copy, guide notes, and optional reference controls.
_Avoid_: stock Show in user-facing copy; describing a Built-in Show as read-only; implying its session draft is a personal template record, durable content, or a separate preview implementation.

**Property animation** (in a Show):
A saved change in one numeric Clip, Effect, Pattern-instance, routing, or
Show-wide property. The destination entity owns the target value while an
incoming boundary may own an explicit start, duration, and easing. Several
properties may inherit one boundary's timing and an individual property may
override it. Typed keyframe tracks may remain Scene-partitioned in the saved
composition and compiler lowering, but the production editor projects their
meaningful changes onto the unified Timeline rather than exposing a second
Scene-local authoring scope. Instance time and public Pattern controls remain
instance-owned; placement view, Clip Transform, overlay opacity, and Effect
parameters remain placement-owned. Unanimated values stay inline and create no
empty lanes. Clip Detail projects all tracks owned by the selected Clip through
one **Animations overview** reached from the persistent `Animations — N`
summary. It groups placement-owned and shared Pattern-instance targets, reports
Show-global endpoint ranges, and navigates back to each target's owning field.
The overview owns removal, keeps validator-identified orphan tracks visible and
removable, and treats tracks with more than two keyframes as read-only without
rewriting their stored points.
_Avoid_: describing compiler Scene partitions as user-facing authoring objects;
representing internal Scene boundaries as a second timeline hierarchy;
silently dropping orphan tracks or coercing multi-keyframe tracks into
two-point ramps.

**Clip Transform** (in a Show):
The canonical placement-owned 2D pose for one compatible clip: Position X/Y, signed Rotation, and Scale X/Y. The UI presents Rotation in degrees, while the Show stores turns around the normalized Stage center `(0.5, 0.5)`. The compiler applies scale, then rotation, then position before authored Transform Effects, Distort, Address, Pattern render, and Color/output stages. Neutral values are omitted from the artifact. Clip Transform has a stable placement target, so its static values and Property animation survive Effect-stack changes. **Mirror** is a separate placement-owned adaptation shown as the fixed first row of the Effects Transform stage; it is not part of the ordered Effect stack and cannot be moved, duplicated, or animated.
_Avoid_: treating Clip Transform or Mirror as another ordered Effect; storing degrees; implying Clip Transform replaces advanced Translate, Rotate, Scale, or Shear Effects that may be composed after it.

**Clip Viewport Aperture** (in a Show):
The visible silhouette inside a Clip Viewport's frame. The frame stays the placement-local X/Y/Width/Height rectangle in normalized Zone coordinates; the Aperture chooses what shows inside it from the spatial silhouette catalogue shared with the Shape-reveal Transition family (#690) - **Rectangle** (the compact default), **Ellipse** (inscribed in the frame; a square frame makes it a circle, and the pad's Shift corner drag keeps frames square), **Diamond**, **Ring** (with a ring-width fraction), **Rounded box** (with a corner-radius fraction), **Cross**, **Regular polygon**, **Heart**, **Star**, **Crescent**, **Cloud**, **Cat head**, **Side-profile cat**, and **Bastet**, each with its Portal parameters; shape parameters belong to their shape and drop when the shape changes. An Aperture may **rotate** its silhouette inside the still-axis-aligned frame and may **invert**, cutting the silhouette out instead of admitting it. The **Edge** is Hard, **Soft** (a bounded feathered band and the default for every shape), or **Dither** (the band thresholded by a pixel-stable spatial hash - binary per pixel, never shimmering, one Pattern evaluation per pixel under coverage-directed composition). Hard and Dither apply only when explicitly authored. The Soft width defaults from device density (`1.5 / sqrt(pixelCount)` in the artifact, so it tracks the actual Controller) and may be authored in Zone units. The Aperture clips the Clip's contribution after Pattern capture; Content pans, scales, and rotates independently behind it, and Freeze/Strobe capture the complete upstream frame before it applies. Distinct from the preview **Viewport** camera.
_Avoid_: coupling Aperture geometry to Content transforms; calling the Stage camera an Aperture; treating the Soft band as a second Pattern evaluation on the current post-capture path; persisting a separate circle shape.

**Transition** (in a Show):
A stable junction between two connected Clips on one Layer. A Transition carries
a visual kind, duration, easing, and type-specific configuration; a
zero-duration Cut remains an explicit selectable junction. Destination Clips
own Clip-level property targets, Show targets remain Show-owned, and the
incoming boundary owns how explicit start values reach those targets. The saved
compiler representation may lower a junction through an internal Scene
boundary without making that Scene an authoring object. Zone Layout intervals
share the Show time axis but remain routing structure rather than Clip
Transitions.
_Avoid_: storing Transition intent as outgoing-Scene decoration; calling Zone
Layout changes Transitions; using Transition as a synonym for every property
curve.

**Effect** (in a Show):
An ordered visual operation owned by a clip. Opacity changes the captured source output toward the Show background, which is black on the flat track. Luma key and Chroma key instead derive an alpha matte from the captured color: Target selects the removed luminance or RGB color, Tolerance removes the inner band, and Softness feathers its edge. Vignette multiplies captured RGB by a radial Stage-coordinate matte with authored center, aspect, radius, softness, and amount. A static full-Stage Vignette may bind one exact scalar-field plane for its Show lifetime; animated, routed, conflicting, or otherwise ineligible cases retain the same inline formula. A keyed top overlay evaluates first; a fully opaque result skips covered render-pure lower sources, while holes and feather pixels evaluate every source required for the exact composite. Translate, rotate, scale, and shear compose in authored order as one affine content transform; the renderer applies its inverse to the Pattern's local sample. Wrap is the explicit post-transform address policy and never changes transform order. Effect values are ordinary clip-level Property targets, so the incoming boundary owns their explicit starts, durations, and easing without adding an Effect clock. Ordinary Effects retain one Pattern evaluation per output pixel. A selected two-layer content-key stack costs `N + U`; a selected three-layer stack costs `N + U1 + U2`, where each `U` is the remaining uncovered or feathered set at that depth. Exact zero-weight render-pure layers are not evaluated, exact full weight bypasses blend arithmetic, and stateful or unproved renderers retain required calls. Effects are not scene-to-scene Transitions. This Show meaning of Opacity is distinct from the preview-only Solidity terminator fade.
_Avoid_: clip effect when **Effect** is unambiguous; treating Effect order as a Transition sequence; saying Wrap is another affine operation; describing a content key as a free second render on every pixel; conflating Show Opacity with viewport Solidity.

**Show output Effect**:
An ordered visual operation applied after the complete Stage composite rather than owned by one clip. Trails is the first Show output Effect. For each linear-RGB channel it emits `max(live, previous * retention)`, so bright motion decays into the current frame without a fourth full-output plane. Ordinary live preview and Controller playback carry previous-frame history continuously. A preview seek still reconstructs exact Pattern state, but clears Trails history until the target frame so scrubbing remains responsive. A required Transition snapshot temporarily owns the shared three planes; Trails suspends and clears during the boundary, then seeds again from the first complete post-boundary frame.
_Avoid_: calling a Show output Effect a clip Effect; claiming Trails history is reconstructed during a seek; implying Trails allocates a second RGB framebuffer.

**Custom map**:
A **map** the user owns — listed in the personal **Maps** tree, openable in **map mode**, and deletable. Provenance, not mechanism, is what makes it custom. Authored custom maps carry **source + baked output**: editable plain-JS map source (a `function(pixelCount){ ... return coords }` or literal coordinate array) plus the coordinate array it baked to, together with integer **grid dims** when the baked points form a regular lattice. There is no explicit save: like a Pattern, source **auto-bakes on the editor's periodic sync tick** whenever it parses (eval via plain `new Function`, float64, no shim). Auto-baking only refreshes the stored map record; it does **not** apply the map to the running preview. To exercise a custom map visually, the user explicitly chooses it in the preview **Map** control. Controller-imported maps are the source-less sibling: frozen coordinate records read from `/pixelmap.dat`, with display-only import provenance and optional map fingerprint, still stored as personal Maps but not editable as Mapper source.
_Avoid_: user map (fine in casual UI prose, but the canonical term is custom map).

**Mixin**:
A reusable Pixelblaze-dialect transformation source with structured header directives (`@param`, `@target`, `@wraps`) and a pass-kind badge (`inject`, `intercept`, or `bind`). Mixins stay generic: parameter values live in Controller or Show bindings, and generated call-site rewriting is surfaced through the **transform summary** rather than baked into the mixin record.
_Avoid_: saying a mixin carries per-controller values; those belong to the binding or pass recipe.

**Stock mixin**:
A **Mixin** that ships with the IDE — revealable in the **Mixins** rail, openable read-only in **Mixin mode** at `/studio/mixins/<stock-id>`, cloneable into a personal Mixin, but never mutable or deletable. Stock Mixins are reference material for the pass engine and for users learning the source shape.
_Avoid_: built-in mixin when contrasting provenance in the rail; say **stock mixin**.

**Personal Mixin**:
A user-owned **Mixin** stored in D1, listed in the personal **Mixins** tree, openable in **Mixin mode**, editable, renameable, and deletable. Its parameters stay generic in source and are bound where the Mixin is used (Controller or Show), never inside the Mixin record.
_Avoid_: implying a mixin carries per-controller parameter values; those belong to the binding.

**Template** (stock-map):
The verbatim plain-JS **source** of a source-backed **stock map** used as the starting point for a new **custom map**. This is now a secondary aspect of **Stock map** rather than a separate primary object: the user opens the stock map read-only, then **clones** it into a custom map. A template copy carries **source text only** — never name (user-set) or `dim` (inferred at bake from the returned arity).
_Avoid_: seed (reserved for the example clouds' historical IDB rows); preset.

**Recommended settings** (curated-pattern → settings):
A purely **IDE-side**, preview-only table of the settings a curated pattern (a **demo**) is meant to open with, so it shows off at its best without forcing anything (e.g. Aurora Sphere recommends the Sphere shell map, 2,048 pixels, and low solidity). It is the single shared presentation used by Gallery detail and Studio; Gallery cards may reduce only its realized count for performance. It is *not* part of the Pixelblaze universe — the physical **Controller** knows only patterns and maps, never associations — and it lives **nowhere in the pattern source or the transpiled artifact**: it is one registry keyed by curated-pattern id, **layer 2** of the **settings cascade**, consumed by the settings resolver as the default whenever a pattern has no per-pattern override for a field. Any subset of the cascaded fields may be recommended (map, pixel count, solidity, normalize, shape/surface, brightness, speed, and the hybrid comfort prefs light size / diffusion); a field with no recommendation falls through to the user **global-sticky** or **developer default** below it. Every recommended value stays freely overridable; the recommendation only sets the baseline a user's own adjustment outranks. Applies to **demos** (read-only *code*, no `PatternRecord` — but a demo still carries its own persisted layer-1 override bag in `patternStore.demoOverrides`, keyed by demo name, so a user's tweaks outrank these recommendations and survive a reopen); a **custom pattern** has no recommendation layer — just defaults + its own overrides. The three earlier sibling registries (recommended map, recommended pixel count, recommended solidity) are **collapsed into this one**.
_Avoid_: baking the association into pattern source or a `//@map` comment (would pollute the artifact); "required map" / "bound map" (it is only a default, never a constraint); treating the old three separate registries as distinct concepts (one table now).

**Settings cascade**:
How every tunable preview setting resolves to an effective value: four layers, first hit wins, top-down — **per-pattern override** → **recommended** (curated patterns only) → user **global-sticky** (comfort prefs only) → **developer default**. Per-pattern overrides are **sparse** (`Partial`) and written *only* on genuine user manipulation of a control (never inferred from a stored value equalling a default — those are indistinguishable). Field partition: **per-pattern cascaded** (`mapId`, `shapeId`/`surfaceId`, `pixelCount`, `solidity`, `normalize`, `brightness`, `speed`); **hybrid comfort prefs** (`lightSize`, `diffusion` — global-sticky baseline *and* per-pattern overridable); **pure global** (`fidelity` — one sticky value, never cascaded). Layer-1 overrides live on `PatternRecord.settings` for a user pattern and in `patternStore.demoOverrides` (keyed by demo name) for a demo — both persist and seed identically. **Forking** a demo snapshots its *effective* settings into the new record as explicit overrides (a frozen copy, no live pointer back). **Resetting** clears whichever layer-1 bag is active — a demo **reverts to recommended**, a user pattern **resets to app defaults** (global-sticky comfort prefs are read, not cleared) — surfaced as a rewind icon by the Preview header that appears only when overrides exist.
_Avoid_: calling any preview setting "global, not per-pattern" as a blanket rule (only `fidelity` is purely global now).

**Map mode** (of the editor):
One of the editor pane's flavors, beside editable-Pattern (with a compile-good/broken badge), **Mixin mode**, and **Library mode**. Opened by clicking **New Map** (a fresh **custom map** on the default skeleton), by clicking an existing custom map in the personal **Maps** tree, or by opening a **stock map** read-only as an example; shows that map's **source** (its `function(pixelCount)`), carries its own header/buttons, and gets a parse-based compile badge. A stock map in map mode is read-only and cloneable into a custom map, analogous to a **demo** Pattern, but it can still be sent directly to a **Controller** because trying shipped maps on hardware is a normal map-debugging workflow. Distinct from assigning a map to a Pattern (the preview's **Map** control) — no map action in the **left rail** or editor applies itself to the running preview automatically: opening, cloning, editing, auto-saving, or auto-baking a map does **not** change any Pattern's active map selection, per-Pattern settings, or currently running preview. There is no **Deploy to preview** map-mode action; the preview **Map** control is the explicit path for using a map with the running Pattern. The right pane is the **map context pane**: a wire-order geometry diagnostic with map facts and honest provenance. Its Map-owned diagnostic viewport preserves physical 2D aspect, centres 3D geometry on its actual bounds, draws all 3D positions as an additive x-ray rather than hiding them behind depth occlusion, limits index labels, and reports coincident coordinates explicitly. Orbit controls are shared interaction language, but Pattern light size, diffusion, brightness, depth, and solidity do not style this diagnostic. It is a wiring/debugging view, never a Pattern renderer.
_Avoid_: map editor (fine in prose, but the canonical term for the editor's state is map mode).

**Mixin mode** (of the editor):
The editor pane flavor for personal and stock **Mixins**. It shows Pixelblaze-dialect source, validates the structured Mixin header (`@param`, `@target`, `@wraps`) with the same good/broken badge surface, and leaves binding values unresolved until the Mixin is used. Stock Mixins are read-only with **Clone**; personal Mixins auto-save clean source on the editor sync tick and can be renamed or deleted from the rail/header. The right pane becomes a provenance surface: usage rows and the last transform summary when those exist, with honest empty states until the pass engine records them.
_Avoid_: implying opening a mixin applies it to the current pattern or Controller.

**Library mode** (of the editor):
The editor pane flavor for personal and stock **Libraries**. It shows Pixelblaze-dialect source and validates with the same good/broken badge surface: dialect parse plus the Library content rule (top level = function declarations, `var` declarations, comments only). Stock Libraries are read-only with **Clone**; personal Libraries auto-save on the editor sync tick and can be renamed or deleted behind strong confirmation. **New Library** mints an identifier-safe default name (`Lib1`-style — the name is the namespace, so it can never be free text like "Untitled Library"). Opening a Library never changes the running preview. The right pane is the Library's **live API reference**: documentation generated from its own `//` comments and re-rendered as the user types, plus Library facts (function count, out-vars, stock Libraries it calls). The separate public **API Reference** is the consumer-facing read-only surface; Library mode remains the only source editor.
_Avoid_: implying opening a library applies anything to the preview; a usage/provenance pane ("used by N patterns") — references are soft and untracked by design.

**Square** (the stock plane; UI label):
The default stock 2D **map** — a uniform square grid of glowing LED dots. Squares a bare pixel count up (`cols = ceil(sqrt(n))`) precisely because a count carries no aspect to honour; a **custom map** that *does* carry an aspect is a different, non-square entry. Its dropdown **label is "Square"** (not "Plain 2D" — which lied, since it always coerced to a square); its internal id stays `plane`. Historically this *was* the whole preview (a single global grid, the 2D-only era); now it is one map among many, and the old preview-wide `grid: {rows, cols}` state is retired — the active map's resolved geometry is the sole source of the preview's extent and aspect. `rows`/`cols` survive only as this generator's private parameters. Its internal pixel *pitch* (fit-to-container `spacing`) is a pure layout detail, distinct from **preview light size** — the pitch positions the dots, light size only scales how large they're drawn.
_Avoid_: "Plain 2D" (the old label; coerced to square, so it misnamed); "preview grid" / "the grid" as a global preview concept (there is no global grid anymore — there is the active map's geometry).

**Aspect normalization**:
The single shared pass that maps a map's raw geometry into `[0,1]`. It runs in one of two **Fill/Contain modes** (#174) — both real, faithful Pixelblaze Mapper behaviour, a **per-pattern** user choice (a cascaded field persisted as a sparse override on `PatternRecord.settings`, displayed in the deck's **Pixelblaze** group), defaulting to **Contain**:
- **Contain** (default): **aspect-preserving, anchored to the longest axis** — the longest axis fills `[0,1]`, shorter axes get a proportionally smaller range (a 15×10 map → long axis `0..1`, short `0..0.667`), so no axis exceeds `1.0`. The preview draws the map's true rectangle/box *and* the pattern reads its true proportions, so a circle pattern looks like a circle on a non-square map.
- **Fill**: **per-axis stretch** — each axis normalizes *independently* to `[0,1]`, so a 4:1 map fills the unit square (the pre-#116 behaviour, recovered). Verified on hardware against a `y >= 0.9` test pattern: under Fill `y` reached `1.0`, under Contain it capped low.

Contain establishes the map's aspect-preserving physical `pos`. Fill then re-stretches only the Pattern-observable `sample` per axis; it never moves the preview's pixels or changes the canvas aspect. Implementation: `normalizeAspect` (Contain) and `normalizeFill` (Fill) in `src/engine/maps/normalize.ts`; `applyNormalizeMode` turns resolved Contain samples into Fill live (idempotent-equivalent on Contain output, so no re-bake). "The map is authoritative" — whatever the map's geometry says, the preview obeys; pixel count never overrides shape.
_Avoid_: calling Contain "the only behaviour" (Fill is equally real — Contain was originally the only mode, #174 reopened it); "stretch to fit" for Contain (that's Fill).

**Dimensionality** (of a pattern or map):
Four dimensions may differ and must be named: **Pattern native dimension** is its highest defined render fn; **map dimension** is active `sample` arity; **renderer dimension** is the render fn selected by compatibility policy; **display dimension** is the viewport embedding/draw space. `render` → 1D, `render2D` → 2D, `render3D` → 3D. A `render(index, x)` Pattern is natively 1D; `x` comes from a true 1D map or Pixelblaze's implicit normalized-index convention. Pattern native dimension sets the Recommended map group and default only; it never filters maps or overrides the active map dimension.
_Avoid_: sampling dimensionality (collapses display dimension with arg count — they differ), dimension count.

**Renderer compatibility**:
The pure automatic policy choosing one defined Pattern renderer from the active **map dimension**, matching Pixelblaze firmware 3.66: Index/1D prefers `render` → `render3D` → `render2D`; 2D prefers `render2D` → `render3D` → `render`; 3D prefers `render3D` → `render2D` → `render`. Exact arity wins. Higher-dimensional renderers receive missing coordinates as `0.5`; lower-dimensional renderers keep the leading coordinates and drop the rest. The preview shows a concise explanation only for adapted combinations. Hardware Send plans against the Controller's installed map, not the preview selection: missing-coordinate cases receive a generated exact-arity **renderer adapter**, while known pre-3.66 lower-dimensional fallbacks are blocked honestly. No manual renderer selector exists. `has2DMap()` / `has3DMap()` report exact active map dimension, never Pattern, selected renderer, or display dimension.

**Renderer adapter**:
A pass-engine-generated exact renderer for a Controller map when the selected Pattern renderer needs coordinates that map does not provide. For example, a 2D map plus a 3D-only Pattern adds `render2D(index,x,y)` which calls the authored `render3D(index,x,y,0.5)`. It changes only the generated artifact, costs one extra function call per pixel, appears in the transform summary/source inspector, and is omitted for exact matches and safe lower-dimensional fallback. The exact target name must be free; a conflicting user/library binding is an explicit push error rather than a silent rename because firmware requires the canonical renderer name.

**Sample / position** (of a map point):
Two independent per-point channels. **sample** — the coordinates fed to the render fn (`[x]` for 1D, `[x,y]` for 2D, `[x,y,z]` for 3D); always owned by the **map coordinate view**. With no installed 1D map, the implicit **Index** view supplies `x = index / pixelCount`. **pos** — where the dot is *drawn* (a 2D or 3D point). `pos` is **dual-sourced**: *map-intrinsic* when a map or generated **geometry family** owns real geometry, but *viewport-supplied* when a separate embedding owns presentation. They coincide for a flat grid; they diverge for a ring (sample `[x]` from Index or a 1D map, pos a 2D circle supplied by a **Shape**), a 2D map wrapped onto a cylinder by a preview-only **Surface**, or a generated family whose selected view changes `sample` while retaining the same family-owned `pos`.
_Avoid_: using "coordinates" unqualified — say sample or pos.

**Show sample remapping** (Show compiler):
An authored transform of the local `sample` presented to a Pattern after a Show routing layout has selected a zone and normalized its domain. It never changes Stage Map `sample`, preview `pos`, zone ownership, or the routing layout's internal local index. The shipped synchronized-tiling tracer repeats 1D normalized index position or 2D local X/Y with one Show-wide `repeatScale`; `1` is exact identity. A destination scene owns the target and its incoming visual boundary owns start, duration, and easing through the shared property model. A 2D Pattern keeps its physical/local `index` argument while X/Y repeat; a 1D renderer receives the repeated normalized index domain.
_Avoid_: calling remapping a map, viewport effect, or routing layout; implying that it moves LEDs or reassigns zones; applying an undefined policy to 3D samples.

**Shape** (1D viewport embedding):
The cosmetic path pixels are *drawn* along whenever the active map is Index/1D — line, ring, pole (helix), regardless of the Pattern's native dimension. The Shape changes only `pos`, never the `[x]` sample the selected renderer reads, so it belongs to the **viewport**, not the map. Any Index/custom/imported 1D map can therefore be paired independently with any Shape. A Shape's display dimension may exceed the map's (Pole displays in 3D). The **Surface** is its 2D sibling — same kind of thing (a viewport embedding owning `pos`), one dimension up. Selected in the preview's **embedding** dropdown.
_Avoid_: calling a 1D shape a "map"; calling a 2D/3D map a "shape"; using "shape" for the 2D embedding (that is a **Surface**).

**Surface** (2D viewport embedding):
The 3D form an active ordinary **2D map's** flat field is *drawn* on — **flat** (the identity surface) and **cylinder** (a tube), regardless of Pattern native dimension. The 2D sibling of **Shape**: it owns `pos` while the map keeps owning `sample`. A surface consumes the map's aspect to set its geometry and must be composed with a source map. This preview-only Cylinder surface choice is an embedding, not a map; it remains distinct from the generated **Cylinder geometry family**, whose views are hardware-real maps over one owned wall point set. **Only developable forms qualify as viewport Surfaces**: a 2D field cannot wrap distortion-free onto a sphere, and a cube net does not accept an arbitrary `cols×rows` map. The viewport Surface set therefore remains Flat + Cylinder.
_Avoid_: calling a surface a "map" (it owns `pos`, not `sample`); "drape" / "drape cylinder" (the cylinder is one surface among several now); reusing "shape" for it; treating sphere/cube/torus as Surfaces (they are 3D maps).
_See also_: **Solidity** — the **cylinder** surface supplies a **surface normal** and is **solid-eligible**; the flat identity surface is not (it faces the camera); **shell** maps are the *other* solid-eligible family.

**Shell / volume** (3D-map geometry):
The two ways a **3D map** (`sample = [x,y,z]`, hardware-real) can distribute its points — orthogonal to the **Surface** mechanism, which only ever wraps a *2D* map. A **shell** puts points on a boundary (Sphere shell, Cube shell, Star shell); a **volume** fills the interior (Sphere volume, Cube volume, Star volume). The catalogue suffixes the label — "Cube (shell)" / "Cube (volume)" — whenever a shape ships in both forms. A **shell** map is **solid-eligible** (it supplies a per-point outward normal: face normals for a faceted shell, generic `normalize(pos − centroid)` for a convex one — see **Solidity**, **Surface normal**); a **volume** map never is (no boundary normal). A **wireframe** (points along edges, e.g. the retired star) or an **irregular cloud** (a measured tree) is neither shell nor volume and not solid-eligible.
_Avoid_: "cloud" for a *filled volume* (cloud means an *irregular measured* set — overloading it collides); "solid" for the filled distribution (it collides with the **Solidity** slider — say **volume**).

**Viewport** (or **camera**):
The display side of the preview — orbit/turntable, fit-to-container, ephemeral **zoom magnification**, depth cueing, **preview light size**, the **diffusion** blur, **solidity**, and (for an active 1D map) the Shape embedding. Owns everything about *how* pixels are drawn; owns nothing the Pattern can observe (zoom, light size, diffusion, solidity, and embeddings stay invisible because `sample` is normalized independently). The viewport's control set is gated on the *display* dimension, not Pattern native, map, or renderer dimension. Here **zoom** means magnifying the fitted 3D presentation around its centre, not changing map coordinates, Pattern sampling, or the Show timeline viewport.
Pattern preview, Show preview, and the **map context pane** are separate presentation surfaces with separate policies even when they reuse camera interaction or low-level projection concepts. In particular, the Map diagnostic viewport does not inherit Pattern preview settings.
_Avoid_: conflating viewport light size with map geometry — neither light size, diffusion, nor solidity ever reaches `sample` or the hardware; describing the Map diagnostic as a Pattern preview with a fixed color buffer.

**Solidity**:
A preview-only, **per-pattern** display property of any normal-bearing embedding or generated geometry: a continuous slider `0 = transparent → 1 = solid` that suppresses **back-facing** points so a solid object hides its own back, while `0` is exactly today's see-through draw. Defined by the presence of a per-point **surface normal**, including the Cylinder viewport embedding, every Cylinder coordinate view, and shell maps. Ineligible: flat embeddings, volumes, measured clouds, and wireframes. Eligibility is **provenance-gated**, not geometry-inferred: a normal is available only because the IDE owns the generator. Mechanically a soft **terminator fade**: a `normal · viewDir` brightness multiplier folded into `project3D` beside the **depth cue**. Default `1.0`; persisted as a sparse per-pattern override and never serialized to a Controller.
_Avoid_: "opacity" (collides with alpha-blending and reads as a **diffusion** sibling); "back-face culling" (names the hard-cull mechanism rejected for the soft fade); treating it as a global viewing-comfort pref like light size / diffusion (it is per-pattern, intrinsic to *what the object is*).

**Surface normal** (or **normal**, preview-side):
The per-point outward unit vector a solid-eligible embedding or **shell** map supplies so the preview can compute **solidity**. Preview-only — re-derived from the generator (the cylinder's analytic radial formula; a faceted shell's face normals; or `normalize(pos − centroid)` for a flagged convex **shell** stock map), **never** stored in a **map** record or sent to a **controller** (a Pixelblaze map is positions only). Absence of a normal is exactly what makes an embedding or map solid-ineligible (Flat, every **volume** map, wireframes).
_Avoid_: implying a normal lives in the map or reaches hardware (it is a viewport construct).

**Preview light size** (or **light size**):
A purely cosmetic viewport control setting how large each drawn light source (the glowing dot in 1D/2D, the orb in 3D) appears, as a fraction of the inter-dot pitch — so "almost touching" lands at the same felt point in every dimension regardless of pixel count or camera zoom. It grows the light sources *in place*: positions and the layout's extent never move (the line keeps its length, the plane/cube keep their bounds). A preview-only construct — never serialized into a **map** and never sent to a **controller** (that physical density is the map's job, not this). A **hybrid comfort pref** in the **settings cascade**: a user **global-sticky** baseline (set once, applies everywhere) that a curated pattern may **recommend** and that the user may **override** per-pattern.
_Avoid_: "spacing" (the old name — it implied moving the dots apart, which it never did); "LED size" / "dot size" (read as hardware or undersell the 3D orb); conflating with **diffusion**; calling it "global, not per-pattern" (it is now a hybrid cascade field).

**Diffusion**:
A purely cosmetic viewport control blurring the drawn light sources together, like a physical diffuser over real LEDs. At 0 the sources are crisp and individually distinct; at full diffusion they merge into an opaque field with no individual source visible. Strictly independent of **preview light size** (it never changes a source's size) and of **brightness** (the field never looks darker overall as diffusion rises — energy is conserved; peaks may soften but nothing dims). Mechanism may differ per display dimension so long as the *feel* is uniform across 1D/2D/3D. Preview-only — never serialized into a **map** or sent to a **controller**. A **hybrid comfort pref** in the **settings cascade**: a user **global-sticky** baseline that a curated pattern may **recommend** (a foggy plasma that looks wrong crisp) and that the user may **override** per-pattern.
_Avoid_: "glow" (the old PRD term); letting diffusion change brightness or source size; calling it "global, not per-pattern" (it is now a hybrid cascade field).

**Precise renderer**:
The opt-in high-fidelity renderer (Fast is the default), running the preview with the same 16.16 fixed-point numeric behaviour as the hardware (range ±32768, precision ~1/65536, int32-wrap overflow, faithful multiply) so that what the preview shows matches what a physical Pixelblaze does. The underlying numeric behaviour is _fixed-point fidelity_.
_Avoid_: Fidelity mode, emulation accuracy, hardware mode.

**Fast renderer**:
The default renderer: plain float64 instead of fixed-point fidelity, for smooth everyday editing. Flip to Precise when hardware-faithful numbers matter. A speed-over-truth toggle.
_Avoid_: fast preview, float mode, preview accuracy off.

**Divergence**:
A difference between preview output and real-hardware output. Two independent kinds: _numeric divergence_ (float64 vs 16.16 — closed by fixed-point fidelity) and _algorithmic divergence_ (the shim's `perlin`/`prng`/transcendentals implementing different algorithms than firmware — documented, not chased).

**Divergence harness**:
A test rig that probes a real Pixelblaze (via `getVars` on a sentinel pixel index) to characterise a built-in's true output and compare it against the preview, quantifying divergence per built-in.

## Example dialogue

**Dev:** When the user hits Download, do we ship the metadata too?

**Domain expert:** No — Download and Copy both emit only the transpiled artifact's `code`. The metadata (which vars are exported, which controls exist) is only used to wire up the var watcher and the controls in the preview. The hardware never sees it.

**Dev:** And if a pattern calls `sdf.circle()` which itself calls `sdf.smoothMin()`?

**Domain expert:** The transpiler inlines both — it follows transitive references within and across libraries. Only the functions actually reached get inlined; the rest of the library is tree-shaken out so the artifact stays small enough for the hardware.

**Dev:** What about `hsv()` — is that a library function?

**Domain expert:** No, `hsv` is a built-in. It's not namespaced and it's not inlined — the runtime provides it. A library is the stuff under `src/pixelblaze/lib/`, always referenced with a namespace.
