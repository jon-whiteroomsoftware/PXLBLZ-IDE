# Issue 405 moving-split results

The production moving split uses one scalar and one ownership comparison per
pixel. Eight equivalent 16x16 split snapshots require a 2,048-element packed
table and substantially more source. Emulator timings are operation-count
proxies; Controller FPS remains the hardware source of truth.

Generated by `npm run issue405` from the production Show compiler and the same
two continuously advancing Pattern members.

| Strategy | Representation | Source B | Routing scalars | Routing elements | Route comparisons/px | Fast ms/frame | Precise ms/frame |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Continuous moving split | coordinate predicates | 10,950 | 1 | 0 | 1 | 0.096 | 0.258 |
| Eight enumerated splits | packed pixels | 93,892 | 0 | 2,048 | table lookup | 0.196 | 0.273 |

The parametric form is continuous between targets; the enumerated comparison
can only step among its eight baked positions. Both forms select one routed
Pattern renderer per physical pixel and advance both member clocks once per
frame. The parametric form was faster in both emulator modes in this run, but
emulator timings vary with host load and are not hardware claims.

## Human gate

Controller verification must compile and activate both production artifacts,
sample FPS at the same configured pixel count, and visually confirm continuous
ownership, local-domain renormalization, endpoint behavior, and uninterrupted
Pattern motion. Record the Controller model, firmware, pixel count, bytecode
sizes, FPS range, and visual result before closing #405.
