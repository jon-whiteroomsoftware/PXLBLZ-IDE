The scene strip should read like a stage plot, not a form

Today every element of the Show editor — axis legend, scene headers, zone labels, pattern cells, transition markers, and all three inspector panels — is the same 1px-bordered zinc box at the same font size. Nothing tells you what is content, what is structure, and what is controls.

The fix is not decoration. It is three different visual vocabularies for the three different kinds of thing on screen, plus one inspector that follows your selection instead of three permanent panels.

A first-time user should be able to muddle through: see the grid as zones × scenes without a legend, click anything to find out what it is, and grow the show from affordances that live where the growth happens.

The five moves

Each one attacks a specific way the current screen fails to communicate. Together they are the difference between "a bunch of boxes" and a surface you can muddle through, CapCut-style.

1 · One header (#351)

The pane header owns identity — name, badge — exactly like the pattern and map panes. The editor's duplicate title row is deleted; View generated and Push move up beside it.

2 · The strip is a surface, not a card

The composition area is recessed — darker ground, inset shadow, full-bleed — so it reads as the stage everything else serves. Inspectors sit on ordinary panel ground. Two surfaces, two jobs, visible from across the room.

3 · Clips carry zone color

Zone color stops being an 8px dot. The zone rail gets a solid color bar; every clip in the row gets a color edge and tinted fill (Ableton's session view move). Pattern names become the largest type in the grid — they are the content. Headers lose their boxes and become labels.

4 · Transitions are seams, not cells

A transition is a dashed vertical seam between scene columns with a cost-colored glyph — visibly a different species from a clip. A holding clip physically crosses the seam, which makes the hold-vs-restart geometry self-explanatory. Seams are clickable, which fixes the panel that today can only ever edit the first boundary.

5 · One inspector, driven by selection

Cell, Transition, and Zones panels collapse into one contextual inspector: click a thing, edit that thing. Nothing selected shows show-level setup. This is the editing model every video and audio tool trains people on, and it removes six identical boxes from the default view.

What stays

The compile bar (budget honesty) survives untouched. So does the PRD model — scenes as columns, zones as rows, transitions as first-class separators, holds as geometry. This is a re-skin of the agreed design, not a re-spec.

Muddle-through gaps this pass surfaced

Styling aside, three functional gaps guarantee a new user gets stuck. The overhaul bakes in the affordances; these need engine/store work regardless of which skin ships.

  • You cannot add a scene. No addScene exists in the store or the UI — every show is stuck at the default two scenes. The mock's + scene ghost column needs a real action behind it.
  • Only the first transition is editable. TransitionInspector hardcodes scenes[0]; boundaries beyond the first can never be changed. Selection-driven seams fix the interaction; the store needs per-boundary addressing.
  • Scene names and durations don't look editable. They are inline inputs styled as static text. Hover affordances (dotted underline, pencil) advertise the edit.

Palette, mono voice, and accent discipline follow #182: amber live strictly for selection and live actions, structural zinc for labels, status green only for health. Zone colors are content, drawn from the existing ZONE_COLORS palette. Comparables studied: Ableton Live's session view (clip grid, track color, contextual clip view) and CapCut (recessed timeline, seam transitions, selection-driven inspector).
