# Native global routing and scalar animation during Transitions

`prepareShowV2ForCompile` preserves global Layout occurrence switches while
participant Layer Transitions use the existing routed placement schedule. A
Layout boundary does not create a new Pattern runtime, restart, appearance
owner, or Scene boundary. The existing compiler recipe already represents its
routing switches independently of that placement schedule.

Only the formerly refused participant combination selected into the qualified
routed Transition path with multiple Layout occurrences, and whole-output windows
containing an interior Layout edge, use this projection. An actual changed-definition
switch or explicit transfer at the exact whole-output window end also needs the
global channel; already-admitted same-Layout scalar boundaries retain their original
path. Its complete ordered occurrences provide global switch
anchors, Layout identities and existing incoming-transfer duration/easing/
direction. Repeated identical definitions need no switch unless a transfer is
explicitly authored. Split-position baselines retain the initial occurrence and
subsequent occurrence parameters at their global boundaries. Existing scalar
track lowering overlays half-open activation, exact retained curves and baseline
restoration. Persisted content is never cropped, resampled or rewritten.

Previously admitted single-Layout participant, whole-output and global-section
routes retain their existing recipe and generated bytes. Existing availability,
source eligibility, RL08–10 and unrelated unsupported representation guards
remain unchanged. Invalid disappearance of a contribution
Zone refuses before transient derivation; no rerouting or partial result occurs.

The direct `lowerShowCompositionV2ForCompile` API returns a legacy-shaped Show
whose routing changes must attach to Scene ends. It cannot represent these new
global switches without changing the placement schedule. It therefore throws
`ShowV2PreparedRecipeRequiredError`, code `requires-prepared-recipe`, only for
these previously refused richer routes, including held participant repeat-scale
animation. Existing non-held-repeat direct refusals remain unchanged. Public preparation is the complete
consumer path. The sole non-test wrapper `lowerShowV2PilotPreview` has no remaining
production caller; the opt-in route already uses captured prepared bundles and
native exporters. No admitted direct caller silently loses routing.

[Consumer tests](../../../src/engine/showLayoutTransitionPreparationV2.test.ts)
first prove the compiler recipe premise independently, then compare reopened
native `.epe` Fast/Precise output and immediately copied private member state
against independently authored global switches/scalar ramps. They cover
before/start/interior/end/after participant windows, repeated/changed definitions,
instant/timed transfer, nonlinear ordinary/retained split-position animation and
exclusive restoration, linked held Groups, effective sharing and authored
first-contribution Restart. Typed Group Make Unique admission now saves/reopens
this formerly refused shape once through existing history/provider protections.
The prior Cut-only Group UI capture remains historical proof of its original
fixture, without claiming a compiler limitation.

## Continuous independent sampling remains unqualified

A continuous record otherwise selected into flat emission retains the prior-domain
refusal when it combines participant Layer Transitions and multiple Layout
occurrences. It cannot silently attach routing to shifted Scene ends, drop a
switch, or report ready with altered sampling. Public preparation returns an
`unsupported-layout-occurrences` diagnostic; direct lowering fails closed. Checked
Layout admission retains the original record/history and performs no adoption or
provider write for such a candidate.

The first review exposed a one-Zone, rank-zero, opacity-one independent-sampling
counterexample: outgoing0..400, crossfade400..600, incoming600..1000 (or
incoming600..800 plus a linked800..1000 Clip). Switching the second physical
Layout at600 could emit at800, an800 switch could disappear, and700/900 could
refuse incidentally. These forms now refuse consistently and atomically.

Replacing flat independent sampling with routed span sampling is not lossless in
the physical2D case: at125ms the same mapped source produces
`[1,.25,.75,1,.75,.25]` versus `[1,0,.5,1,1,.5]` with identical private clocks.
The complete existing flat compiler recipe, augmented with zones, Layouts,
member-zone bindings and global switches, rejects scene boundary modes. These
primary consumer witnesses remain an unresolved adapter/sampling obligation,
carried in the #1038 residual ledger
([audit scope map](../evidence/issue-1038-audit/scope-map.md), R8). They are not
an accepted compiler limit or a guarantee of universal combination support. No emitter/domain widening or remapping workaround
is introduced. Single-Layout admitted source bytes stay identical; qualified
routed native output, sharing and first-contribution Restart remain covered.

## A participant Transition in a multi-Zone continuous-flat Show

`canLowerToFlat` admits a participant Transition regardless of the Show's Zone
count. The exact boundary is one clause, evaluated once per Transition: every
Clip other than its two participants must end strictly before the outgoing Clip
ends, or start strictly after the incoming Clip starts. Flat sections split at
every Clip edge, so such a Clip is absent from the outgoing hold, the window and
the incoming hold alike, and the whole-output Scene-boundary blend sees only the
two participants. A Clip that overlaps the window, or merely touches either edge
- where the blend would fade it in or out instead of cutting it - keeps the
atomic `unsupported-zone-sampling` refusal and its existing diagnostic,
`composition.clips: lowering requires repeat-mode Clip sampling evidence before
compilation.` So does a Clip that spans the Show across a Transition.

Nothing else changed. `canLowerToFlat` still requires whole-Show sampling of
`independent`, rank-zero Layers, opacity one and single-key appearance, so a
record already admitted on the routed Transition or global-section route keeps
its route, recipe and generated bytes: the widening admits only records that
refused. The continuous-flat multi-Layout refusal above is unchanged and now
answers more records, because a multi-Zone independent Show with a Transition
and a second Layout occurrence reaches it instead of refusing for sampling.

v1 is the oracle, and a byte oracle. A multi-Zone flat v2 record lowers to the
same legacy Show v1's own `addShowZone`, `splitShowAtTime`, `placeShowClip` and
`addShowScene` produce, so both compile through the same routed emitter to the
same source and Effects bytes. One consequence worth naming: a two-Zone Show
wraps its Show clock at Show End (`% showEndMs`) where a one-Zone flat Show
holds its last Clip - v1 behavior, arriving in v2 at the same edit.

[Consumer tests](../../../src/engine/showCompositionLoweringV2MultiZoneTransition.test.ts)
build each admitted case as a v1 record through v1's own owners and require
identical generated source; the fresh-Show case additionally replays the
reopened `.epe` in Fast and Precise, comparing frames and every member's
exported state before, inside and after the window and across Show End. The
[census table](../evidence/issue-1063-flat-transition-multizone/census-lowering.json),
measured before the widening, pins the route, recipe and artifact of all 87
inventoried records; `scripts/show-v2-parity.test.ts` checks it.

## Participant repeat-scale animation

Participant Transitions also preserve Show repeat-scale tracks through the existing
`samplePropertyRamps.repeatScale` recipe channel. Ordinary and retained kernels
retain exact activation, source coefficients, half-open evaluation and baseline
restoration. A descriptor-free full-Show held track maps to its authored global
cuts once. Retained kernels are never mistaken for held cuts merely because their
ordinary easing fields say `hold`. These new participant admissions do not change
previously accepted whole-output or global-section recipe generation.

An explicit whole-output split-position Property ramp continues across an interior
Layout switch. The ramp retains its complete existing compiler representation;
a simultaneous occurrence baseline cannot overwrite its positive half-open carrier.
The projected carrier is bounded to `[0, transition.durationMs]` before occurrence
baselines are filtered, the same upper bound `normalizePropertyTransitions` already
applies to a Scene Property ramp. The v2 validator accepts a longer authored duration,
so an overlong carrier ends at its Transition window end instead of running past it,
and the occurrence cuts it would otherwise have swallowed keep their authored times.
An occurrence cut outside the bounded carrier, including one exactly at its exclusive
end, remains present and reaches delivered output. Timed Layout transfer
identity, duration, easing and direction remain independent of contributor schedules.
No authored record is mutated, no runtime is cloned or reset implicitly, and no
compiler, emitter or persisted schema is widened.

[Global consumer tests](../../../src/engine/showGlobalTransitionAdaptersV2.test.ts)
first prove both existing compiler channels independently. Public reopened records
then produce native reopened `.epe` Fast/Precise frames and immediately copied
private state matching independent scalar/switch schedules: nonlinear/retained/held
repeat animation, shared first-contribution Restart, interior/end switch boundaries,
instant/timed transfers, explicit scalar carriers and atomic availability/conflict
refusal. The conversion scalar regression retains original whole-output source
bytes, then proves both changed split and repeat participant targets through native
output at their persisted global boundary. The 47-record parity corpus stays exact.

### Short scalar carrier classification

Newly admitted global whole-output recipes retain authored Property ramp durations
1, 99 and 100ms directly, bypassing the legacy Scene Property minimum in this
transient projection. Only the upper Transition-window bound applies, so these short
carriers stay exact while an overlong one is clamped to its window. Independent raw compiler recipes and native reopened
Fast/Precise output qualify the mapping. Previously admitted edge-at-window-start
records retain their existing source bytes, including the pre-existing 1/99-to-100ms
coercion in `showModel.ts`'s `clampPropertyDuration`. That older coercion remains
unresolved, carried in the #1038 residual ledger
([audit scope map](../evidence/issue-1038-audit/scope-map.md), R11). It is neither
an established compiler limit nor a claim of universal exact short-carrier support. The committed
[base/suffix witness](../evidence/issue-1038-global-transition-adapters/short-carrier-witness.json)
records the same public inputs, outcomes, ramp durations and source hashes.
